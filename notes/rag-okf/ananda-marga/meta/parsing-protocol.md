# Principle

Build **source-first**: curated, citation-anchored concepts extracted *from the
actual texts*, not from a model's parametric memory. The OKF layer is the
durable source of truth; a later GraphRAG / vector index is a derived,
regenerable consumer of it. Quality (doctrinal fidelity) outranks cost.

# Two-layer model

Each work is stored as **two linked layers**:

- **Verbatim layer** (`layer: verbatim`, `type: SourcePassage`) — exact source
  text, one passage per natural unit, generated by a **deterministic split
  script** (never hand-typed → zero drift), under `works/<work>/`.
- **Concept layer** (`layer: concept`) — the paraphrased, cross-linked ontology;
  each concept cites its passages via `sources` + body links.

A later RAG / GraphRAG indexes either layer or both (hybrid: concept finds →
passage grounds). The `layer` field is the ingestion selector.

The same `layer` filter keeps the graph tractable: at scale, build `viz.html`
over a **concept-only view** (drop every `layer: verbatim` doc) — verbatim
passages bloat the HTML and add thousands of disconnected nodes.

**Passage unit per genre** (verbatim layer):

| Genre | Passage unit | Ref / anchor |
|-------|--------------|--------------|
| Aphorisms (Ánanda Sútram) | sūtra + purport | `C-S` (e.g. `1-1`) |
| Discourse collections (Ananda Vacanamrtam, Subhasita Samgraha) | one discourse | `part-NN/<n>-<slug>` + date/place |
| Q&A / talks (Baba in Fiesch) | session / Q&A pair | `<date>/<n>` |
| Long section | sub-window by heading | `<parent>#pNNN` |

# Pipeline

1. **Source intake.** Register each work in [works/](/works/) as a `Work`
   concept with language, edition, and translator (the provenance backbone).
   Then generate its **verbatim layer** — split into per-unit `SourcePassage`
   docs (`layer: verbatim`) under `works/<work>/` with a deterministic script.
2. **Structural split.** Segment each work by discourse / chapter / section
   with stable anchors (`work-id` + section/sūtra/page). Mechanical and
   lossless; this is scaffolding, not the deliverable.
3. **Grounded extraction.** An LLM reads each segment and proposes atomic
   concepts (one idea per file), **grounded in the segment text** (retrieval-
   grounded — never free-wheeling from memory). It emits canonical name +
   `aliases` + `sanskrit` + `sources`.
4. **Reconciliation.** Merge proposals across segments into one canonical file
   per concept; fold transliteration variants into `aliases`; capture multiple
   senses / period-evolution instead of flattening them.
5. **Linking.** Add typed relationships (`## Relationships`: is-a, part-of,
   stage-of, cause-of, opposed-to) plus markdown links; create [glossary/](/glossary/)
   `Term` anchors for the controlled vocabulary.
6. **Verification (quality gate).** Adversarial fidelity pass: flag
   interpretation vs direct teaching, catch syncretic drift, preserve apparent
   contradictions with provenance; optional practitioner review.
7. **Conformance.** `okf_lint` to 0/0, `okf_viz` to inspect the concept graph.
8. **Retrieval layer (later).** Feed the curated corpus to vector RAG and/or
   GraphRAG. The OKF files remain the source of truth and audit surface.

# Concept model

- **Unit = one idea per file**, not one page or chapter. Granularity is the
  single biggest quality lever (see open decisions).
- Canonical name in `title`; every spelling in `aliases`; original term in
  `sanskrit`; backing texts in `sources`.
- Body: `# Definition` (Sarkar's framing + quote) → `# Explanation` →
  `## Relationships` → `# Notes` (fidelity flags) → `# Citations`.

# Fidelity guards (anti-syncretism)

- Do not normalise concepts toward generic Vedanta / yoga / Western philosophy.
- Preserve the distinctions Sarkar draws deliberately (e.g. his Tantra vs
  classical Sāṃkhya; his novel microvita ontology).
- Separate **direct teaching** (quotable) from **interpretation** (flagged).
- Keep contradictions visible across periods; let provenance, not smoothing,
  resolve them.

# Design decisions

**Resolved (2026-06-19):**

1. **Transliteration** — **IAST with diacritics is canonical** (e.g. `kośa`,
   `saiṋcara`, `Prakŕti`); simplified ASCII and Sarkar's Roman Saṁskṛta go in
   `aliases` for search.
2. **Granularity** — **fine: one idea = one file** (a file per vṛtti, per PROUT
   principle, etc.). Maximises graph richness and downstream multi-hop / GraphRAG.
3. **Pilot** — **Ánanda Sútram**, the ontological spine (its sūtras seed
   cosmology, ethics, and the five fundamental principles of PROUT).

4. **Corpus source format** *(resolved)* — decided per work at intake. Ánanda
   Sútram = local Electronic Edition plaintext (`Ananda_Sutram.txt`); its verbatim
   layer is built by a deterministic split script.

**Still open:**

5. **Relationship typing** — default is prose in `## Relationships`; a structured
   frontmatter field for machine-queryable edges can be added later if needed.
