# Библиотека контента: не генерировать дважды (общий кэш в базе)

> **Источник:** перенесено из `galaxica/docs/design/CONTENT_LIBRARY_DB.md` (2026-08-11).
> **Для Tantra Yoga это:** принцип «write-once/read-many» для контента из 218 книг
> Шастры: цитаты, карточки терминов, примеры — подготавливаем один раз (сверка с
> `notes/shastra/skill-index.md` и `sources/`), храним в общей базе, игра только читает.
> Таблицы `content_word`/`content_association` → у нас `content_term` (термин + перевод +
> цитата + источник) и `content_quote`.

> Статус: **черновик-видение** для подписи автора (2026-08-02).
> Связан: `docs/design/MINIAPP_VISION.md` (мини-апп берёт контент отсюда).
> Идея автора: LLM-генерация (слова, озвучка, истории, ассоциации) происходит ОДИН раз,
> сохраняется в базу и дальше просто подтягивается для всех пользователей — дёшево и быстро.

---

## 1. Проблема

Сейчас часть контента генерируется заново для каждого пользователя или на каждый запрос:

- переводы и примеры слов (LLM);
- ассоциации для Замка памяти (LLM, по 3 штуки на слово);
- озвучка (TTS — ElevenLabs, стоит денег за каждый синтез);
- истории/эпизоды (LLM, дорого; уже есть гейт публикации, но нет общего «пула»).

Каждая повторная генерация = деньги (LLM + TTS) и задержка для пользователя.

## 2. Что уже кэшируется (инвентаризация — приятная неожиданность)

| Что | Где сейчас | Статус |
|---|---|---|
| Слои учебного контента (алфавит, когнаты, лестница слов, LEGO-каркасы, частотные слова) | таблица `content_pack` (lang, iface_lang, kind) — JSONB | ✅ уже общий кэш: сгенерили для пары (язык, интерфейс) — все читают |
| Истории/эпизоды (outline, сцены, словарный состав) | таблицы `episode` / `scene` / `episode_vocab`, статусы draft → published (гейт автора) | ✅ уже «библиотека историй»: опубликованные видит каждый |
| Озвучка (TTS) | файловый кэш `media/audio/cache/{lang}/{sha256}.ogg` | ✅ файловый кэш по тексту — повторный синтез того же текста не платит |
| Озвучка сцен историй | `episode_audio` (CLI, .ogg на диске) | ✅ |
| Корпусы слов (частотность, домены) | `frequency_corpus`, `domain_corpus` | ✅ |
| Персональные слова/примеры/ассоциации | `words`, `examples`, `fsrs_state`, `deferred_associations` | ⚠️ персональные — это правильно, но «лучшее» из них не обобщается |

**Вывод: фундамент уже есть.** Не хватает трёх вещей: общего пула «слово→озвучка→пример»,
популярности ассоциаций и правил, по которым новое поколение автоматически пополняет
общую библиотеку.

## 3. Целевая модель: общая библиотека (новые таблицы)

Идея: **контент — это данные, а не генерация**. Таблицы ниже — «полки» библиотеки.
Ключ уникальности везде — (язык, интерфейс, поверхность слова/фразы) — чтобы одно и то же
слово не генерировалось дважды ни для кого.

### 3.1. `content_word` — словарный пул (главная полка)

Одно слово на (lang, iface_lang, surface):

- `surface` — слово на изучаемом языке (например, "hello");
- `gloss` — перевод на язык интерфейса (уже есть в `content_pack`, переносим в общий вид);
- `example` — пример употребления;
- `example_gloss` — перевод примера;
- `audio_ref` — ссылка на озвучку (существующий файловый кэш или `content_audio`);
- `image_ref` — картинка слова (если есть);
- `source` — кто создал: сид / LLM / автор;
- `status` — черновик / готово / отклонено;
- `usage_count` — сколько раз выдано пользователям (для аналитики);
- `created_at`.

**Жизненный цикл:** первый запрос на слово (любым пользователем, из бота или мини-аппа) →
если нет в пуле → генерируем (LLM + TTS) → сохраняем → все последующие читают из базы.
Повторная генерация невозможна по построению (уникальный ключ).

### 3.2. `content_association` — коллекция лучших ассоциаций

Ассоциация = мнемоническая зацепка к слову («hello похоже на „халло“ → здороваемся с
Халком»). Сейчас LLM генерирует 3 варианта каждому пользователю заново.

Новая полка:

- `word_id` (ссылка на content_word);
- `text` — текст ассоциации;
- `type` — по звучанию / по картинке / пользовательская;
- `choose_count` — сколько раз пользователи ВЫБРАЛИ эту ассоциацию для Замка;
- `status` — черновик / опубликовано.

**Правило «лучшее видно всем»:** при генерации ассоциаций для нового пользователя сначала
показываем ТОП-2 по `choose_count` из библиотеки (уже обкатанные людьми), и только если их
нет — генерируем новые. Выбор пользователя увеличивает счётчик. Так лучшие ассоциации
«выигрывают» естественным отбором, а генерация со временем почти исчезает.

### 3.3. `content_audio` — полка озвучки (опционально, поверх файлового кэша)

Файловый кэш уже есть. Добавляем таблицу-реестр (lang, text_hash → файл, провайдер,
стоимость, created_at), чтобы: считать реальную экономию TTS, переиспользовать озвучку
в мини-аппе (игра слушает те же файлы), и при смене провайдера не терять файлы.

### 3.4. Истории — уже библиотека (`episode`), добавляем правила

Опубликованные эпизоды уже общие. Добавляем:
- `episode.usage_count` / популярность (сколько раз начали/дослушали);
- автоматическое предложение новых эпизодов: когда мини-апп/бот «дочитал» корпус слов —
  генерируем следующий пакет фоново, автор публикует гейтом (как сейчас).

## 4. Правила жизни библиотеки

1. **Write-once / read-many:** генерация только при первом запросе; дальше — чтение.
2. **Дедупликация по построению:** уникальные ключи (lang, iface, surface) — дубль невозможен.
3. **Популярность решает:** ассоциации/примеры сортируются по реальным выборам пользователей.
4. **Гейт автора для «в библиотеку»:** LLM-новинки попадают в общий пул как черновики,
   автор публикует (как уже работает с историями). Личные слова пользователя (из Замка) —
   не в общий пул автоматически, только если автор/модерация захочет.
5. **Никакого удаления:** контент не удаляется, только меняется статус (черновик/готово/
   отклонено) — «сгенерили один раз» значит «навсегда».
6. **Версии:** при смене промптов/модели новые генерации идут с `version` — старые остаются
   в базе и продолжают работать.

## 5. Экономика (грубая оценка выгоды)

- Озвучка (ElevenLabs): синтез ~1–3 цента за слово-фразу. 1000 слов × 10 пользователей:
  сейчас до 1000 синтезов ≈ до $10–30; с библиотекой — 1000 синтезов один раз ≈ $1–3,
  дальше $0. Экономия растёт линейно с числом пользователей.
- LLM-переводы/примеры: аналогично — один раз на слово вместо N раз.
- Ассоциации: 3 генерации на слово → 1–2 генерации только на НОВЫЕ слова; популярные
  слова со временем вообще не генерируются.
- Истории: уже сэкономлено гейтом публикации; добавляется повторное использование
  в мини-аппе (одна история = бот + миссия в игре).

**Итог:** чем больше пользователей, тем дешевле каждый следующий. При 100+ активных
пользователях стоимость контента на пользователя стремится к нулю.

## 6. Интеграция: бот и мини-апп из одного пула

- Бот: Замок памяти, лестница слов, истории — читают `content_word`/`content_association`.
- Мини-апп: задания (карточка/сбор фразы/аудирование) — читают те же полки.
- Пользовательские данные (какие слова выучил, FSRS, Замок) — остаются персональными
  (`words`/`fsrs_state`), библиотека — общая. Это разделение уже есть в модели данных.
- Итог: одна генерация питает и обучение, и игру; прогресс синхронизирован.

## 7. Что делаем первым (порядок работ)

1. **Миграция/перенос:** `content_word` из данных `content_pack` (не дублируя: паки остаются,
   слово-пул строится поверх как «развёрнутый вид»).
2. **Путь «нашли → нет → сгенерили → сохранили»** в точках, где бот запрашивает слово/пример
   (сначала — лестница слов и карточки Замка).
3. **`content_association` + счётчик выбора** в цикле Замка памяти (там уже есть выбор из 3).
4. **Реестр аудио** (`content_audio`) и подключение мини-аппа к тем же файлам озвучки.
5. **Популярность историй** (`usage_count`) и фоновый пре-ген новых эпизодов под гейт автора.
6. Метрики экономии: «сколько генераций сэкономлено» — строка в /pilot.

## 8. Открытые вопросы на подпись автора

1. Публиковать ли пользовательские ассоциации в общую библиотеку (анонимно, при
   «это лучшая») — или только LLM-варианты и ручные? (По умолчанию: только после выбора
   ≥3 раз другими пользователями, анонимно.)
2. Пре-генерировать ли слова целыми пакетами фоново (ночью, под гейт) или только по
   запросу первого пользователя? (По умолчанию: гибрид — по запросу + ночной пре-ген популярных тем.)
3. Лимит объёма библиотеки на старте: начинаем с темы «базовые 500 слов» для английского?
   (По умолчанию: да, 500 слов + фразы из них.)
