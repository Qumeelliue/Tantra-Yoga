## 1. Идея одним абзацем

Есть два уровня продукта, связанных одним аккаунтом и одной базой:

1. **Оперативный уровень — агент-чат** (то, что уже работает): живой разговор,
   истории, объяснения, Замок памяти. Агент — доброжелательный друг-тренер.
2. **Игровой уровень — мини-апп**: 3–5 минут в день, короткие задания-миссии,
   питомец, серия дней, лиги. Игра — не «развлечение вместо учёбы»,
   а **та же учёба в игровой обёртке**.

Любой прогресс в одном уровне виден в другом. Контент и методика — общие.

## 2. Учебное ядро (что реально заставляет запоминать)

Игра ради игры не учит. В основе — проверенные когнитивные механизмы:

### 2.1. Единицы знаний (knowledge items)

Любой предмет раскладывается на атомарные единицы:

| Тип единицы | Язык | Физика | Химия | Правила/история |
|---|---|---|---|---|
| Факт (вопрос-ответ) | «как будет „собака“?» | «что такое ускорение?» | «формула воды?» | «когда началась ВОВ?» |
| Понятие | слово + значение | сила/энергия | элемент/соединение | термин |
| Правило/формула | грамматическое правило | F = m·a | валентность | правило дорожного движения |
| Навык/применение | собрать фразу | решить задачу | уравнять реакцию | применить правило к случаю |

Универсальное представление единицы: **{вопрос, ответ, объяснение, пример, сложность, тема}**.
Для языка добавляется озвучка; для физики/химии — числа и единицы измерения.

### 2.2. Когнитивные типы заданий (лестница нагрузки)

Одно и то же знание тренируется на 4 уровнях глубины:

1. **Распознавание** (легче всего): выбрать правильный ответ из 4 — «узнать».
2. **Припоминание** (active recall): ввести ответ самому (слово, число, формулу) — «вспомнить».
3. **Применение**: решить задачу/собрать фразу — «использовать».
4. **Построение**: составить объяснение/диалог/решение — «владеть».

Правило: **игра всегда чередует уровни** — распознавание даёт быстрый успех,
припоминание и применение дают реальное усвоение. Только «выбор из 4» не учит —
это узнавание, а не знание.

**Маппинг мини-игр на уровни (каталог GAME_MECHANICS_PIPELINE §11):**

| Уровень | Форматы мини-игр |
|---|---|
| 1. Распознавание | Блиц-пары, Картинка-слово, Аудио-квиз, Memory-пары, Сортировка по полкам |
| 2. Припоминание | Карточка-светофор (самооценка), Cloze-пропуск, Spelling-гонка, Wordle-клон |
| 3. Применение | Собери фразу, Cloze в контексте, Мягкие гонки |
| 4. Построение | Мини-диалог со спутником, Shadowing, «История дня» |

Правило микса: раунд = 1–2 задания распознавания (быстрый успех) + 2–3 припоминания/
применения (усвоение). Игра с одним лишь распознаванием помечается «разминка» и даёт
меньше корма питомцу — усвоение вознаграждается сильнее узнавания.

### 2.3. Интервальные повторения (SRS)

Повторение по кривой: через 1 день → 3 → 7 → 14 → 30 (в боте уже работает FSRS —
переносим как есть). Повторение в игре — НЕ скучная рутина, а «полив сада» / «кормление
питомца» / «защита замка»: то же действие, игровая метафора. За повторение — награда,
как за новое знание (или чуть больше).

### 2.4. Чередование тем (interleaving) и эффект тестирования

- Перемешиваем темы в блоке (не «10 раз одну тему подряд») — так мозг учится
  различать, а не механически повторять.
- «Проверка» (тест без подсказок) — не наказание, а главный инструмент запоминания:
  каждый блок заканчивается мини-проверкой («испытание»), за него — повышенные награды.

### 2.5. Микро-формат

Сессия 3–5 минут: 1 новый элемент + 2–4 повторения + 1 мини-проверка. Закончено —
можно выходить с чувством «сделал». Длинные сессии — опция, не норма.

### 2.6. Прецеденты: этот движок уже работал (на других предметах)

Универсальность не гипотеза, а проверенный паттерн — те же «карточка/задача + прогресс +
игра» применялись к разным предметам (ресёрч 2026-08-02):

| Игра | Предмет | Механика | Урок для нас |
|---|---|---|---|
| DragonBox | алгебра | абстракция вводится неявно: «вычисти переменную» = решаешь уравнение | сложное можно спрятать в игру без теории |
| Prodigy Math | математика | MMORPG: решаешь примеры → бьёшь монстров | RPG-прогресс удерживает школьников |
| CodeCombat | программирование | код — единственный способ управлять героем | «ошибка в игре = ошибка в предмете» |
| Kerbal Space Program | физика | песочница с настоящей орбитальной механикой, «весёлые провалы» | учёба через эксперимент и провалы без штрафа |
| Algodoo | физика | рисуешь механизм — физика «проверяет» сама | симуляция как автопроверка |
| Kahoot!/Quizizz | любой предмет | квиз-шоу со скоростью; обзор 93 исследований — рост вовлечённости | простейшая механика, сильный соц. эффект |
| Brilliant | STEM | «думай сам — потом ответ», недельные лиги ~30 | проверка без подсказки + малые лиги |
| Duolingo | язык | короткие уроки, SRS, стрики; курс ≈ 4 семестрам (Jiang et al., 2022) | микро-урок + серия = реальный результат |
| QuizUp/Trivia Crack | общие знания | дуэли 1×1, 7 раундов по 10 секунд, баллы за скорость | дуэль — сильный, но «аддиктивный» формат (см. §6.4) |

## 3. Игровая оболочка (предметно-независимая)

Всё ниже НЕ знает, какой предмет учит игрок. Это конфигурация.

| Механика | Роль | Предмет-независимость |
|---|---|---|
| Питомец/растение/замок | визуальный прогресс, эмоциональный центр | растёт от «единиц знаний», каких — неважно |
| Серия дней (streak) | главный двигатель возврата | универсальна |
| XP и уровни | долгий прогресс | универсальны |
| Монеты + магазин косметики | трата, статус | универсальны |
| Дневная цель | микро-норма 3–5 минут | универсальна |
| Сезоны и ивенты | новизна, возврат «старичков» | универсальны |
| Лиги ~30 человек, Friend Quests | соц. мотивация | универсальны |
| Рейтинг «среди своих» + процентиль | азарт без стыда: «ты в топ-5%», «до топ-100 — 320 очков» | универсальны (предмет — только фильтр списка) |
| Профиль-витрина (спутник, дом, медали) | статус, «заглянуть к соседу» | универсальна |
| Коллекция спутников (вид = предмет/язык) | «собрать всех», повод начать новый предмет | универсальна (каждый предмет — свой вид) |
| Мир/дом спутника (полянка → дом → район → город) | видимый статус и трата монет | универсален |
| Статистика и личные рекорды | для «любителей цифр»: графики, точность, «лучше 80% игроков» | универсальна |
| Сундуки (переменные награды) | азарт, 1–2 в неделю | универсальны |
| Испытание/босс | проверка темы, «экзамен без страха» | собирается из единиц темы |

По MDA (механики → динамики → эстетики): **механика «карточка с вопросом» одна,
а «эстетика» (вызов, открытие, забота) — любая**. Игровая оболочка конфигурируется
под предмет/аудиторию без переписывания ядра.

### 3.1. Испытания («боссы») — ключевой игровой-учебный паттерн

Каждая тема (10–15 единиц) заканчивается «испытанием»:

- 5–7 заданий без подсказок, уровни 2–3 когнитивной нагрузки (припоминание/применение);
- только из единиц, которые уже встречались в этой теме;
- награда за испытание — крупная (корм + сундук + «значок темы»);
- при неудаче — не провал: показываем слабые места, «попробуй ещё раз» без штрафа,
  подсказки остаются.

Испытание решает две задачи: реальная проверка усвоения (а не «прошёл и забыл»)
и игровой пик эмоций (аналог босса в RPG).

## 4. Манифест предмета (как движок узнаёт предмет)

Новый предмет подключается КОНФИГУРАЦИЕЙ, без изменения движка:

```
предмет: {
  id: "en" | "physics" | "chemistry" | "rules",
  название, иконка, цвет,
  единицы_знаний: [ {вопрос, ответ, объяснение, пример, тема, сложность, аудио?} ],
  типы_контента: [карточка, число, формула, конструкция, выбор],
  автопроверка: [точное совпадение | число+единица | формула-токены | порядок слов],
  генератор: [шаблоны | LLM-промпт | оба],
  озвучка: [нет | TTS-язык],
  темы: [ {id, название, порядок} ],
  srs: [окна повторения],
}
```

### 4.1. Автопроверка ответов по типам контента

| Тип ответа | Как проверяем | Примеры |
|---|---|---|
| Выбор | точное совпадение id варианта | язык: перевод; физика: единица измерения |
| Текст | нормализация (регистр, пунктуация) + допустимые синонимы + regex-шаблоны для грамматики | язык: ввод слова; правила: ответ-факт |
| Число | число + допуск (±погрешность, единицы измерения) | физика: F = 20 Н |
| Формула | сравнение токенов / символьное упрощение (CAS — как в DragonBox) по списку допустимых эквивалентов | химия: H₂O; физика: v = at |
| Конструкция | порядок элементов (слова фразы, шаги решения) | язык: сбор фразы; химия: уравнение |
| Код/схема (позже) | исполнение/симуляция (как CodeCombat, Algodoo) | программирование, схемы |

LLM генерирует и варианты ответов, и **список допустимых эквивалентов** (синонимы,
другие формы), чтобы проверка была честной. Всё сохраняется в библиотеке контента.
Правило: **LLM генерирует, проверка всегда детерминированная** (эталон + валидатор) —
иначе ошибки ИИ разрушают доверие.

### 4.2. Генерация контента

- **Шаблоны** (детерминированные): числа, задачи с параметрами, спряжения — бесконечные
  варианты без LLM (для физики/химии — основное).
- **LLM** (для сложного): объяснения, примеры, истории, диалоги — через библиотеку
  контента (генерируем один раз, дальше читаем).
- Гибрид: шаблон создаёт каркас, LLM — текст/объяснение.

Прецеденты масштаба: Duolingo запустил 148 AI-сгенерированных курсов (2025), Memrise —
LLM-мнемоники и ИИ-собеседник. Правило остаётся: LLM генерирует, проверка —
детерминированная, и всё попадает в библиотеку контента (write-once/read-many).

## 5. Единый аккаунт: агент-чат + мини-апп (одна база)

| Данные | Где живут | Как синхронизируется |
|---|---|---|
| Профиль, язык/предмет, уровень, XP, серия | единый профиль пользователя | общий |
| Выученные единицы + SRS-состояние | персональные таблицы знаний | общий: и бот, и игра читают/пишут |
| Контент (слова, задачи, истории) | библиотека контента (общая) | общий |
| Игровые ресурсы (монеты, корм, питомец) | игровые таблицы | игра пишет, бот читает |
| События/статистика | habit_events (уже есть) | общий |

**Как агент участвует в игре:**

- Агент — «голос» питомца в чате: «Питомец проголодался — 3 задания, и он счастлив»;
  «Твоя серия 12 дней — не дай ей погаснуть!» (мягко, без вины).
- Достижения игры приходят в чат (агент поздравляет, объясняет, что дальше).
- То, что игрок выучил в игре, агент использует в разговоре (общие слова), и наоборот:
  слова из Замка — «знакомые» в игре (растят питомца быстрее).
- Один аккаунт = единая история и единый прогресс: человек не «переключается между
  продуктами», а пользуется двумя поверхностями одного.

## 6. Психологические принципы (для любого предмета)

### 6.1. Три базовые потребности (Self-Determination Theory)

Автономия (выбор тем/темпа), компетентность (видимый рост каждый заход), связанность
(доброжелательный агент + друзья/лиги). Ключевой вывод: **внешние награды (баллы) снижают
внутреннюю мотивацию, а информативная похвала — повышает.** Награды у нас «информативные»:
XP/корм сообщают «ты усвоил и продвинулся», а не «мы тебя оцениваем».

### 6.2. Драйверы Octalysis — какие задействованы

| Драйвер | Где у нас |
|---|---|
| Развитие и достижения | уровни, медали, точность |
| Владение и накопление | питомец, коллекция косметики, монеты |
| Социальное влияние | лиги ~30, Friend Quests, агент-друг |
| Потеря и избегание | серия дней (мягко: фриз/воскрешение, без катастроф) |
| Непредсказуемость | сундуки 1–2 в неделю |
| Дефицит и нетерпение | сезонные предметы, «завтра откроется» |
| Смысл и призвание | «ты реально учишься, питомец — символ знаний» |
| Творчество и обратная связь | свои ассоциации для Замка, кастомизация |

### 6.3. Flow: адаптивная сложность

Состояние погружения требует баланса «вызов = навык». Реализация: **сложность подстраивается
под игрока** — после серии ошибок упрощаем (меньше вариантов, подсказки), после серии успехов
усложняем. Правило: никогда не «стена», всегда следующий шаг достижим.

### 6.4. Ошибки образовательных игр и противоядия (из ресёрча)

| Ошибка (пример) | Противоядие у нас |
|---|---|
| «Брокколи в шоколаде»: игра приклеена снаружи, обучение внутри не изменилось (Bruckman/Habgood) | **Сплав**: игровое действие = учебное задание. Нет «сначала учись, потом играй» |
| Pay-to-win (Prodigy: платная подписка даёт преимущество — жалоба в FTC) | За деньги только косметика; знания и рост питомца — только учебой |
| Фарм/читерство (боты в лидерборде Memrise; «оптимизация под XP» в Duolingo) | Баллы = знание: награды только за правильные ответы; антифрод; капы |
| Давление и вина (Duolingo: «сердца»-жизни, сова давит на совесть) | Мягкие состояния, никаких штрафов за ошибку, фриз серии |
| Аддикция без системности (QuizUp: увлекательно, но знания фрагментарны) | У нас предмет = курс: единицы, темы, испытания, SRS |
| Вовлечённость ≠ результат (RCT Duolingo 2017 не дал разницы с классом; мета-анализы: эффект большой, но разброс огромный) | Меряем не только заходы, но и образовательные метрики (слова/SRS/точность) |
| Тамагочи-наказание (StudyGotchi RCT: смешанные результаты от чувства вины) | Питомец только растёт/ждёт; пропуск не наказывает |
| Публичные лидерборды → стыд и отвал | Только малые лиги + «призраки» друзей + личный рекорд; рейтинги ПРИВАТНЫ по умолчанию (игрок сам включает витрину) |
| Лутбоксы/«казино»-дропы (Fortnite — штраф FTC $245 млн) | Сундуки — только бесплатная косметика, редко; никакого азарта за деньги |
| FOMO-давление и confirmshaming («точно уйдёшь?») | Никакого искусственного дефицита; «серия сгорит» — факт с решением (фриз/воскрешение), не манипуляция |

**Проверенное противоядие в основе:** частые низкоставочные квизы реально улучшают
успеваемость (мета-анализ Sotola & Crede, 2021) — наша «проверка = обучение»
(испытания тем, тесты без штрафа) опирается на это.

## 7. Что это даёт бизнесу (стратегия)

- **Один движок — много предметов**: языки → физика → химия → правила ПДД → экзамены.
  Каждый новый предмет = конфиг + контент-библиотека, без переписывания игры.
- **Один агент — много игр**: тот же доброжелательный агент ведёт чат по предмету
  и связывает с соответствующей игрой.
- **Экономика контента**: библиотека (см. `CONTENT_LIBRARY_DB.md`) — генерация один раз
  на предмет, дальше — чтение. Стоимость на пользователя падает с ростом базы.

## 8. Дорожная карта движка

1. **Язык (MVP)**: движок + манифест языка + мини-апп (тамагочи) + связка с ботом.
2. **Второй манифест** (физика или правила) — доказывает универсальность:
   та же игра, другой контент, шаблонная генерация задач.
3. **Третий+ предметы** по той же схеме.
4. Платформа для новых предметов (конфиг + библиотека) — как «конструктор» для нас.
