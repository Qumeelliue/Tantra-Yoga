# Брейншторм: Propose-Hold-Collapse

Задача: $ARGUMENTS (если аргументы пусты — возьми задачу из контекста беседы).

## Зачем протокол

Авторегрессионная генерация фиксирует первый выбранный путь: раннее «очевидное»
решение затягивает всё продолжение в локальный оптимум. Протокол принудительно
удерживает несколько альтернатив в суперпозиции и откладывает выбор (collapse)
до момента, когда все гипотезы оценены по явным числовым критериям.

## Алгоритм

### 1. PROPOSE — сгенерируй 5 радикально разных гипотез

Не выбирай очевидное. Не фильтруй. Перечисли пять подходов, среди которых должны быть:
- 1-2 «классических» решения,
- 1-2 «нестандартных» или контринтуитивных,
- 1 умышленно дикий (для расширения пространства решений).

### 2. HOLD — для каждой гипотезы

- **Суть** в одной строке.
- **Два возможных побочных эффекта** (что может пойти не так, какие зависимости появятся).

На этом шаге запрещено сравнивать гипотезы между собой и намекать на фаворита.

### 3. EVALUATE — оцени каждую по шкале 1-10

- **Реалистичность** (реально ли внедрить в обозримый срок?)
- **Влияние** (насколько решит задачу?)
- **Риск** (вероятность негативных последствий?)

### 4. COLLAPSE — выбери одну

На основе оценок выбери одну гипотезу для глубокого анализа. Обоснуй выбор. Если
две гипотезы примерно равны — укажи, по какому дополнительному критерию решено в
пользу одной.

## Формат ответа

```markdown
## Гипотеза 1: [Название]
**Суть:** ...
**Побочные эффекты:** ...
**Оценка:** Реалистичность: X/10, Влияние: Y/10, Риск: Z/10

(повторить для всех 5)

## Финальный выбор
**Выбрана гипотеза N: [Название]**
**Обоснование:** ...
**Следующий шаг:** [что делать дальше с этой гипотезой]
```

## Важно

- Если пользователь явно хочет ансамбль из двух агентов (творческая генерация в
  чистом контексте + реализация с жёсткими ограничениями): запусти суб-агента
  «генератор» — без фильтров и оценки реалистичности, только гипотезы с побочными
  эффектами, — затем передай его результат второму суб-агенту «архитектору» для
  числовой оценки, выбора и реализации с контрактами. Если в окружении установлен
  плагин `prompting-methodology`, используй его готовых агентов
  `brainstorm-agent` и `architect-agent`; иначе — двух general-purpose суб-агентов
  с этими ролями в промпте.
- Если запрос пользователя уже узкий и ответ очевиден — не имитируй брейншторм
  ради формы. Скажи прямо: «Здесь не нужен брейншторм, ответ очевиден: X. Если
  хочешь альтернативы — уточни критерий».
